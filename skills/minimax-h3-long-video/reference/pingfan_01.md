# 实战：pingfan_01（《平凡的人生》第一段）

> 命名：本页记录**第一次跑通**时的实况，那批磁盘产物用的是旧短 tag（`pf01s1`、`pf01m1`…、
> `output/final_pf01.mp4`、`projects/pf01/`），按用户决定**不迁移**。自本规范起，新片一律用
> `<film>_<shot-slug>`（示例 spec 已是新命名：`pingfan_balcony`/`pingfan_agespot`/`pingfan_screen`/
> `pingfan_ride`/`pingfan_gate`，成片 `output/final_pingfan.mp4`）。

第一次完整跑通「文本 → 分镜 → 锚图 → 逐段生成 → 成片」的记录，用来校准预期与时间。

## 输入与决策

- 输入：小说片段 **289 字**（李国庆 50 岁黄昏浇花发现老人斑 → 回忆 25 岁骑车接妻子）。
- 换算：中文朗读 3.3–4.5 字/秒 → 全文旁白 **64–88s**。
- 用户选择：**B 版（精选旁白、9 段 ≈45s）**，且**先不配旁白**（只要画面 + 环境声）。
- 画幅：生成 864×480，后期裁 **2.39:1（864×362）**。

## 分镜（9 段：3 独立 + 2 链×3）

| 段 | tag | 内容 | 方式 |
|---|---|---|---|
| S1 | pf01s1 | 阳台浇花，大远景缓推中景，手持，楼下快餐店钠灯虚焦 | 独立 + 锚图 |
| S2 | pf01s2 | 手背老人斑微距特写，指腹抚摸（全片支点） | 独立 + 锚图 |
| S3 | pf01s3 | 纱窗破洞晚风、光斑扫过他脸、望向楼下失焦（切暖调钩子） | 独立 + 锚图 |
| M1-1/2/3 | pf01m1 | 骑行穿城 → `beat 5s` 车筐栀子花 → `beat 10s` 年轻的手握车把（与 S2 同构图） | **链** 3 段 |
| M2-1/2/3 | pf01m2 | 厂门口人流 → `beat 5s` 她看见他轻笑 → `beat 10s` 上车晃动、他稳住车把 | **链** 3 段 |

视觉语法：现实=冷青灰 + 手持呼吸；记忆=琥珀暖 + 稳定器流动。两支点：**三次"手"的特写**（S2 老人斑 /
M1-3 年轻的手 / 结尾回望）与硬切的时间跳跃。

## 锚图（Z-Image Turbo）

- 5 个镜头 × 3 seed = **15 张**，1024×576、8 步、cfg1、res_multistep、ModelSamplingAuraFlow shift3。
- 实测 **~13 min**（首张要装载 encoder+UNet；本机 15GB 内存 swap 抖动，多次"卡" 2–4 分钟）。
- 联系表 `output/pf01/anchors.html` → 控制台 `/files/pf01/anchors.html` 挑图。
- 结果：`s1=b s2=a s3=c m1=b m2=b` → `projects/pf01/anchors/<shot>_best.png`。

## 生成（chain_director_v3，dur=5 / steps=8 / 864×480）

| 任务 | 结果 | 备注 |
|---|---|---|
| pf01s1 | **326s** | 含一次性冷启动（服务+ray+FSDP ≈180s），段本体 ~145s |
| pf01s2 | 180s | 复用常驻服务 |
| pf01s3 | 181s | |
| pf01m1 | **651s** | 3 段 169 + 241 + 232s + 合并；续接段 raw ~164 帧 |
| pf01m2 | **643s** | 3 段 176 + 218 + 242s + 合并 |
| 合计 | **1981s ≈ 33min** | 9 段 |

- 每个任务都带 `--clean`；链带 `--merge`；`--beat 5s:`/`--beat 10s:` 指向第 2/3 段。
- prompt 策略：每条任务固定 prompt（首段动作），动作推进放 beat → 每段一次新的 encode（MISS），
  但 epoch 恒定，ray/FSDP 不重建。

## 组装与验证

```
film.py assemble → output/final_pf01.mp4
  1038 帧 = 43.25s（3×124 + 326 + 326 + hold 14）｜864×362｜7.2MB｜h264 + aac 32kHz
  淡入 0.5s（首帧均值 4.2）｜末帧定格 0.6s 后淡出（末帧 0.0）
  切点帧号 124 / 248 / 372 / 697（段边界）+ 477 / 1013（链内 handover 裁切）
```

端到端 **22:11 开工 → 23:31 出片 ≈ 80 min**（生成 33min + 锚图 13min + 脚本编写/排错/组装 ~15min +
观察等待）。预估 50–70min 偏乐观，主因是锚图阶段 swap 抖动与续接段（raw 164 帧）比预想慢。

## 这次踩的坑（已写进 pitfalls.md）

1. `scripts/assemble.py` 起初在视频流 flush 之后才 `add_stream` 音频 → muxer `SIGFPE`；改成"先建所有流"。
2. 一度以为 slot 没在保存（`output/h3_continuous/` 空）——其实是每个新任务 `--clean` 把上一个的删了；
   链内自己会建。
3. Z-Image 阶段看起来"卡死"（GPU 0%），实为装载/换入换出，等 2–4 分钟即恢复。
4. `ui2api.py` 拒绝 subgraph → Z-Image 的 API 模板手工转换并实测跑通。
5. driver 的 stdout 块缓冲：日志里看不到 `[clip1]`，改用 ComfyUI tqdm + `/history` + 槽位文件监控，
   之后给脚本加了 `python -u`。

## 可复用结论

- **成本锚点**：独立镜头 ~3min/个（warm）、链每段 ~3–4min、冷启动 ~3min、锚图 ~20–60s/张 + 首次装载。
- **9 段 ≈45s 的片子，从写分镜到出片，实际约 1.5 小时**（含审图与排错）。
- 分镜一旦定稿，重跑只在"某个镜头不满意"时发生（单镜 ~3min），所以**分镜阶段多花时间最划算**。
